\section*{Background}
% A1
\paragraph{Application.}
We focus on teaching a robot arm that already manipulates one object to handle a
new one from videos alone, without recording new motor commands. This matters for
warehouse and home robots, where new items arrive constantly and teleoperating
each one is impractical. We study this in simulation with OCBench (UR5e arm,
Robotiq gripper) \citep{ocbench2026}.

% A2
\paragraph{Problem and need.}
Visuomotor policies learn by imitating images paired with the motor commands that
produced them. Recording these commands requires teleoperation, which is slow and
costly: collecting 76k demonstrations took 50 people a year
\citep{khazatsky2024droid}. Videos without commands are cheap (e.g., videos of the same robot generated
by world models or video generation models \citep{jang2025dreamgen}), and inverse dynamics models (IDMs) let a
robot learn from them: trained on labeled demonstrations, an IDM infers the
command between two consecutive frames and labels videos for imitation
\citep{torabi2018bco,baker2022vpt}, needing few labeled examples
\citep{morin2026idmssil}. Our application adds one difficulty:
the videos show an object absent from the labeled demonstrations, so the IDM must
label images that differ from its training data. Formally, given labeled cube transitions
$\mathcal{D}_A=\{(o_t,o_{t+1},a_t)\}$ and unlabeled block videos
$\mathcal{D}_B=\{o_t\}$, we seek an image-only policy $\pi(a \mid o)$ that
succeeds on the block under R1--R6, which requires labeling $\mathcal{D}_B$
accurately without block labels.

\section*{Aims/Goals}
% A3
\paragraph{Goals.}
Train an image-only policy for the block from cube demonstrations and block
videos alone. R4 and R5 are the performance targets; R1--R3 and R6 hold by design.

% A4
\paragraph{Scope.}
We use the visual single-block task of OCBench. The source object is its cube; the
target is a new elongated block, with adapted expert grasps. Cameras, lighting,
goal, and initial positions stay fixed, so the object is the only change. Human
videos, real hardware, other shifts, and large pretrained models are out of scope.

% A5
\paragraph{Proposed solution.}
We adapt the IDM to the block before labeling. Since the arm looks the same in
both domains and only the object changes, the IDM receives each frame with its
difference to the next, emphasizing arm motion, and domain-adversarial training
\citep{ganin2016dann} makes the remaining features indistinguishable between cube
and block while they still predict cube commands. The adapted IDM labels the
block videos for policy training; we also compare aligning the policy instead.

\section*{Feasibility and resources}
% A9
\paragraph{Dataset, resources, and plan.}
We generate all data in OCBench on CPU MuJoCo: \tbd{300} labeled cube
demonstrations and \tbd{200} block videos, with true block actions stored only for
evaluation; no licensing or ethics constraints apply. Training needs one GPU
\decide{source to confirm}, about \tbd{4} GPU-hours per run and \tbd{100} in
total. Open-source domain-adaptation and imitation code lowers
risk. A pilot by
\tbd{October 21} checks the expert, the cube policy's drop on the block, and the
growth of IDM error. Core methods
follow by \tbd{November 1}; evaluation by \tbd{November 18}.

\section*{Risk analysis}
% A10
\paragraph{Pitfalls and mitigation.}
The shift may be too small to matter, as robot and cameras are unchanged; the
pilot measures it, and we can enlarge the change. The block may need actions
absent from cube demonstrations; invariant features can then discard information
needed to predict them \citep{zhao2019invariant}, which per-component errors will
expose. Closed-loop failure is mitigated by chunking; expert failure on the
block, by shortening it. If alignment hurts, we report negative transfer. If time runs short, optional
baselines go first; the core comparison (cube-only policy, unadapted IDM, our
method, reference) stays.
